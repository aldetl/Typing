# Typing 1.5.1

Typing 1.5.1 improves Caps Lock mode switching and updates the command-mode tray icon.

## Changes

- Fixed a phantom held modifier after enabling or resuming Typing while Ctrl, Shift, or Alt was held. Releasing the key now restores isolated Caps Lock and Left Alt mode taps without another disable/enable cycle.
- When Caps Lock is a configured mode key, unmatched presses overlapping another key no longer perform its normal capitalization function. Isolated taps still switch command mode, and configured shortcuts still work.
- The bundled Default profile uses **Caps Lock+Space** to toggle capitalization. Removed its two Right Shift capitalization shortcuts. The existing **Caps Lock** action remains available for custom hotkeys.
- Replaced the command-mode tray icon with a lowered version of the enabled mole, with native frames from 16 to 256 pixels.
- Added the colored default cursor movement key picture at the top of Help, with About above Open User Guide in a right-aligned button column. The README and Markdown user guide use the same picture and explicitly explain Caps Lock+Space for capitalization.
- Made Website and GitHub in About clickable, with Website listed first; each opens its own address in the default browser. The Help picture uses a compact size at half its earlier nominal width and height.
- Expanded regression checks for held modifiers, overlapping keys, repeats, capitalization output, and lifecycle recovery. Updated the English and Simplified Chinese guides.

## Upgrading from 1.5.0

Quit Typing before replacing its executable and matching InputSim DLL. Preserve your `configuration.ini` and `profiles` folder.

Existing profiles keep their explicit bindings. To adopt the Default profile's new capitalization shortcuts, remove `RShiftKey+CapsLock` and `CapsLock+RShiftKey`, retain `CapsLock+Space=CapsLock`, then save and set that profile as active. New extractions include the updated Default profile.

The profile format and pinned InputSim dependency are unchanged. This release does not add automatic recovery for every possible missing keyboard release.

## Packages and verification

- **x64:** Windows 11 x64 portable package.
- **x86:** Windows 7 SP1/Windows 10 target, also usable on Windows 11 through WOW64.

Verification is performed on Windows 11 x64, including x86 execution through WOW64. Build and package checks cover both architectures; native checks cover keyboard capture/output, modifier-held enabling, Caps Lock overlaps, cleanup, and restart. Clean-machine deployment, actual Windows 7/10 execution, physical-key and sleep/session transitions, and full manual display/accessibility coverage remain unverified. These are compatibility targets rather than claims that every target OS has been tested.
